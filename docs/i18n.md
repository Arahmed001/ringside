# Internationalisation (English + Arabic)

English lives at the bare path (`/boxers`), Arabic under `/ar` (`/ar/boxers`). `proxy.ts` rewrites English requests to `app/[locale]/...`
internally and 308-redirects `/en/...` to the bare path, so each page has exactly one URL per language. Crawlers are never redirected by
`Accept-Language`. Every page declares its canonical URL and hreflang alternates (`lib/seo.ts`).

## Writing text
The English sentence is the key; Arabic lives in `i18n/ar.json`; a missing entry falls back to English.

```tsx
const t = await getT();                       // server component / route handler: import { getT } from "@/lib/i18n/server"
const t = useT();                             // client component:                import { useT, useLocale } from "@/components/i18n"

t("Find a fighter")                           // plain
t("{n} fighters", { n })                      // {placeholders}
t.n(count, "{n} fighter", "{n} fighters")     // plurals: the "other" form is the key (Arabic has six forms)
t.rich("Entered rated <b>{r}</b>", { r, b: (c) => <b>{c}</b> })   // markup inside a sentence
t.name(boxer.name)                            // a proper name (fighter, trainer, gym, event, venue, city, nickname) in the visitor's language
t(DIVISION_NAME)                              // a value from a registered set (see lib/i18n/dynamic-keys.ts), or msg("…") in a page-local table
```

Rules
- Keys are **string literals** (the scanner reads the source). No template literals with `${}`, no concatenation; use placeholders.
- Never build a sentence from pieces; one key per sentence, so Arabic can reorder it. Put numbers and names in placeholders.
- A table of labels used with `t(variable)`: wrap each label in `msg("…")` where the table is defined (`const KIND = { gym: msg("Gym") }`), or add the set to `dynamic-keys.ts` if it lives in `lib/`.
- Where the English differs for a woman ("He"/"She", "his"/"her"), use two keys; Arabic verbs are gendered.
- Dates `fmtDate(d, opts, t.locale)`, countries `countryName(c, t.locale)`, division `divisionLabel(wc, sex, t)`, results `methodLabel(m, r, t)`; numbers `n.toLocaleString("en-US")` (Western digits in both languages).
- Links: `import Link from "@/components/L"` (adds the `/ar` prefix). Plain `<a href>`, `<form action>` and `router.push` take `useHref()` / `localePath(locale, path)`.
- Layout: use logical Tailwind classes (`ms-`, `me-`, `ps-`, `pe-`, `start-`, `end-`, `text-start`, `text-end`), never `ml-`/`pr-`/`left-`/`text-left`. Charts, bars, posters and timelines keep red on the left and blue on the right in both languages: give the graphic itself `className="ltr-fixed"` (not its caption).
- Letter-spacing and uppercase do nothing useful in Arabic; `globals.css` neutralises them for `:lang(ar)`.

## Tooling
| | |
|---|---|
| `npm run i18n:extract` | regenerate `i18n/keys.json` and `i18n/client-keys.json` (the slice of the dictionary sent to the browser) |
| `npm run i18n:check` | missing / malformed / unused entries; exits 1 if any are missing or malformed (the test suite does the same) |
| `npm run i18n:translate` | fill missing keys with Claude in batches, with `i18n/glossary.json` for consistent boxing terms (needs `ANTHROPIC_API_KEY` in `.env.local`) |
| `npm run i18n:missing` / `i18n:merge -- file.json` | the same loop done by hand |
| `npm run i18n:names` | proper names (see below) |
| `npm run i18n:review` | native-speaker review: `export` an offline sheet, `import` the reviewer's file, `status`, `qa` (see `docs/arabic-review.md`) |

## Names
Fighter, trainer, gym, event, venue and city names come from the feed in Latin letters. Their Arabic spellings are kept in the committed file `i18n/names.ar.json` (one name per line: `{"ar", "source", "reviewed"}`, sorted by English spelling so a diff shows exactly what changed). At run time they are read from the `name_translations` table (`lib/i18n/names.ts`), apart from the fighter rows so a re-ingest never loses them, and **the database loads the file every time it opens** (`lib/i18n/names-file.ts`), so a fresh checkout has its Arabic names without any script.
- The file is the source of truth, the table is a copy. Loading never overwrites a name that a person reviewed in the database when the file's copy was not reviewed.
- `npm run i18n:names -- import` and `-- auto` (and the review import) save the database back to the file themselves; `-- save` and `-- load` do it by hand, and `-- check` exits 1 if a name the site can show is missing from the file (a test does the same for the demo league).
- Each name records its source (`claude`, `claude-session`, `editor`) and whether a person reviewed it. All 1,848 current names are machine transliterations, none reviewed.

## Review
The Arabic is machine-written until a person says otherwise: see `docs/arabic-review.md`. `i18n/ar.review.json` records reviews, the data page shows the counts, and an approval stops counting the moment the text changes.

**After adding or changing any `t("...")` in a client component (or a file in `lib/`), run `npm run i18n:extract` and commit `i18n/keys.json` and `i18n/client-keys.json`.** The second file decides which Arabic strings are sent to the browser; a string missing from it shows in English on the Arabic site even though the dictionary has it. A test (`the committed key files are current`) fails if either file is stale.

**No English may be left behind on an Arabic page.** `npm run smoke` reads the HTML of every Arabic page of the demo league (client components are rendered into it) and fails on any Latin word of three letters or more in the text, the title, the description or an announced attribute (`aria-label`, `title`, `placeholder`, `alt`), except the brand, units and short capitals, other organisations' names (BoxRec, Wikidata ...) and anything inside an element marked `lang="en"`. Text that is English by nature (a data source's name, a validator's message, the wordmark) gets `lang="en"` (and `dir="ltr"` if it is more than a word): that is also what lets a screen reader pronounce it correctly. Names of people, places and belts go through `t.name()`, never raw. It only sees what the server renders: a string that appears after the page loads in the browser is covered by the key-file test above, not by this one.
